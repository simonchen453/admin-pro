# review-pr

审查 Pull Request 代码，提供专业的代码评审意见。

## 使用方式

```
/review-pr [PR编号或URL]
```

## 审查流程

1. 获取 PR 信息和变更文件列表
2. 分析每个变更文件的代码
3. 生成审查报告

## 审查要点

### 代码质量
- 代码是否清晰易读
- 命名是否规范 (类名、方法名、变量名)
- 是否有重复代码
- 方法是否过长或过于复杂

### 安全性
- SQL 注入风险
- XSS 攻击风险
- 敏感信息泄露 (密码、密钥硬编码)
- 权限校验是否完整

### Spring Boot / Java 规范
- 是否正确使用注解 (@Transactional, @Validated 等)
- 异常处理是否合理
- 日志记录是否恰当
- 是否符合 RESTful 设计规范

### 性能
- N+1 查询问题
- 不必要的数据库查询
- 大对象未及时释放
- 缓存使用是否合理

## 输出格式

```markdown
## PR 审查报告

### 概述
- PR 标题: xxx
- 变更文件数: x
- 新增行数: +xxx
- 删除行数: -xxx

### 问题列表

#### 严重问题
- [ ] 文件:行号 - 问题描述

#### 建议改进
- [ ] 文件:行号 - 建议内容

### 总体评价
[通过 / 需要修改 / 需要讨论]
```

## 执行步骤

当用户调用此 skill 时:

1. 如果提供了 PR 编号，使用 `gh pr view <编号> --json title,body,files,additions,deletions` 获取 PR 信息
2. 使用 `gh pr diff <编号>` 获取代码变更
3. 分析变更内容，按照审查要点进行检查
4. 输出审查报告
